## Ordered steps

1. Confirm the working tree and branch contain only the approved starting state; preserve the pre-existing `client/.env.example` modification outside this feature.
2. Add Tailwind CSS and the Vite plugin, then make the smallest Vite/CSS integration change needed to keep the existing development server, proxy, Vitest, and production build working.
3. Establish the visual foundation in `styles.css`: neutral/light SaaS surfaces, indigo action color, semantic success/warning/error colors, responsive container rules, typography, and accessible focus-visible treatment.
4. Build and test the small reusable UI primitives first so all later screens share the same interaction states and spacing decisions.
5. Extract the application shell and room selector. Keep the desktop sidebar limited to the real booking workflow, collapse gracefully on narrow viewports, and use only fields present in the room API response.
6. Move the current room-loading logic into the application component and implement skeleton, empty, error-with-retry, and multi-room selection states without changing API calls.
7. Refactor the booking form around the selected room. Retain the existing UTC/ISO conversion and conflict-selection logic, then add field associations, inline errors, pending protection, and accessible success/conflict feedback.
8. Extend both locale files for every new visible string and verify that changing language does not reset room/date form state.
9. Add focused frontend tests for each state and interaction, then run client tests, typecheck, lint, build, and the repository `scripts/check` command.
10. Perform the required independent read-only review against the spec, plan, and diff; fix only confirmed findings, map every acceptance criterion to evidence, and update the spec/plan status only after the gates pass.
11. Apply the approved sidebar interaction refinement: branded logo, desktop collapse rail, mobile drawer, Escape/backdrop close behavior, and focused interaction coverage.
12. Keep the desktop shell at viewport height with content-only scrolling, and constrain sidebar text so locale changes cannot alter the expanded or collapsed rail width.

## Risks & open questions

| Risk / question | Recommendation and rationale | Decision |
|---|---|---|
| Tailwind integration could disturb the current Vite/Vitest setup. | Use the official Vite plugin with no PostCSS or router addition; keep the existing proxy and test configuration unchanged. This limits build-surface area. | Open |
| The API can return more than one room, but the old UI always used the first room. | Add explicit selection backed only by returned rooms. Reset the form instance when the room changes so a previous room’s timezone is never silently reused. | Open |
| The current backend exposes no booking list, schedule, or room-management data. | Keep the shell focused on the single real booking workflow and do not show non-functional destinations. This avoids misleading production UI. | Resolved by scope approval |
| A new visual system may require more components than this small app currently has. | Add only primitives used by this flow, with local composition instead of a broad component framework. This keeps the blast radius reviewable. | Open |
| API error text may already be localized by the server. | Render server-provided messages verbatim and use i18n fallback text only when no usable server message exists; never translate or replace stable server error details in the client. | Resolved by spec |
