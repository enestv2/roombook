7. Add `i18next` and `react-i18next`, define typed/bundled English and Turkish catalogs, and

9. Update API request helpers to send the selected language on every relevant request, retain

10. Add client tests. Recommendation: approve `@testing-library/react`, `@testing-library/user-event`,

## Risks & open questions

- **Identity endpoint response shape:** `MapIdentityApi` is framework-owned. Recommendation: first
  use `IdentityErrorDescriber` and shared ProblemDetails customization; only copy/customize an
  endpoint if tests prove a required error cannot be localized, because replacing the framework
  endpoints increases auth and security blast radius.
- **Domain error compatibility:** moving from human text to codes changes an internal constructor
  shape. Recommendation: update all domain tests and keep translation strictly in the API layer;
  this prevents domain behavior from depending on the current UI languages.
- **Client test dependencies:** direct UI verification needs a DOM/test-rendering harness that is
  not currently installed. Recommendation: approve the three development-only testing packages;
  without them, AC-1/AC-2/AC-10 need manual QA evidence rather than automated component tests.
- **Current untracked work:** Git status is currently blocked by repository ownership metadata.
  Recommendation: resolve that environment issue before branch creation and before claiming a clean
  diff; do not modify or discard existing work.
- **Swagger scope:** the feature does not translate Swagger descriptions, but its response schemas
  must expose the additive error-code fields. Recommendation: update only schema/examples and keep
  existing documentation language unchanged.
